# 0016: Document mode (M9)

## Decisions

- **Text content** is read with `includeMarkedContent: true, disableNormalization: true` so item
  indices match the spans PDF.js renders. A text layer span exists only for items with `str !== ''`,
  so `TextLayerMap` maps item index → span index by counting non-empty items (ADR 0007).
- **Layout analysis** (`src/pdf/layout.ts`) runs in a worker (comlink) and is pure:
  - Headers and footers: lines in the top/bottom 7% zones whose normalized text (digits removed)
    repeats on at least 40% of pages; bare page numbers in those zones.
  - Columns: a gutter is an x band where coverage by body-zone items is at most 0.25 × the median
    non-zero coverage, at least max(8 pt, 0.8 × median font size) wide and inside 15–85% of the
    page's x range. Comparing with the median (not the densest column) handles unequal columns;
    excluding the margin zones keeps full-width headers from closing the gutter.
  - Lines are grouped by baseline; a new block starts when the gap exceeds 1.6 × the 0.25 quantile
    of line gaps (the median was skewed by paragraph gaps), on a font size change, or when a line
    starts a list or reference entry (`ITEM_START`: bullets, `1.`, `[12]`, `a)`).
  - Captions (`Figure|Fig.|Table n`) and a References/Bibliography heading's region are typed so the
    reading rules can skip them. Line-end hyphens are joined when the next line starts in lower case.
    A paragraph that ends a page without terminal punctuation continues on the next page.
  - Pages with no text are reported (`emptyPages`) for the M13 OCR path.
- **Highlights** reuse the web painter with multiple ranges (one per page a sentence spans) and the
  same CSS Custom Highlight names; the word cursor is the same overlay, positioned against the
  scroll container. Follow-scroll accepts a scroller element.
- **Storage**: opened PDFs are saved to OPFS as `documents/<sha256>.pdf`, keyed by content hash, so
  the reader URL `?doc=<hash>` reopens them after a reload or browser restart. The library entry is
  written as soon as a document opens (not only after reading), so "Recent documents" lists it.
- **Playback** runs in the reader page's in-page host (ADR 0012); the reader saves positions to the
  library directly.
- **Opening PDFs**: from the reader's file picker or drag and drop, the side panel ("Open in Open
  Reader" when the active tab is a PDF), the link context menu, and an opt-in setting
  (`interceptPdf`, default off) that adds a declarativeNetRequest redirect of top-level `.pdf`
  navigations to `reader.html?src=`. The redirect needs `reader.html` in `web_accessible_resources`.
  `file://` PDFs need "Allow access to file URLs"; the reader explains this instead of failing.
- **PDF.js assets** (worker, wasm, standard fonts, CMaps) are copied into the build under `/pdfjs/`
  so nothing is fetched from the network.

## Consequences

- Reading order is heuristic. The "Show reading order" overlay numbers blocks so mistakes are easy
  to report, and goldens in `tests/fixtures/pdf/*.golden.json` (generated by `pnpm fixtures`) pin
  the behavior.
- Scanned PDFs open but have nothing to read until OCR (M13).

## Addendum (M14): reader lifecycle under React StrictMode

StrictMode mounts the reader, cleans up and mounts it again in one commit. The first mount's
async open now stops when it is cleaned up, so only one open runs, and `ReaderController.destroy()`
tears down on the next tick unless `attach()` runs again first, so the live PDF.js viewer is kept
(a second viewer on the same container does not work). Before this, two opens raced on one
viewer, and the OCR E2E hung about half the time.
